02 / QA WORKBENCH

From requirement
to reproducible test.

A sample test-design exercise for a fictional public-service application portal. Synthetic scenarios, not a test report on SDOC or a client system.

Download sample pack ↓
TC-01Valid application submissionFunctional＋

REQ-01 · Required fields · DESIGN ONLY / NOT EXECUTED

StepsEnter synthetic applicant details, choose a role, attach a permitted PDF, and submit once.

Expected resultOne application is created with a unique reference and confirmation.

TC-02Required-field validationFunctional＋

REQ-01 · Required fields · DESIGN ONLY / NOT EXECUTED

StepsLeave the name and email empty and submit. Repeat with whitespace-only values.

Expected resultSubmission is blocked. Specific errors identify each field and preserve other entries.

TC-03Unauthenticated accessAPI＋

REQ-02 · Access control · DESIGN ONLY / NOT EXECUTED

StepsIn an authorized test environment, request a protected application endpoint without a valid session.

Expected resultThe API rejects the request and returns no applicant data.

TC-04Prevent duplicate submissionRegression＋

REQ-03 · Submission integrity · DESIGN ONLY / NOT EXECUTED

StepsSubmit a valid application twice rapidly, then retry the same request identifier.

Expected resultOnly one application is stored; retries return a consistent outcome.

TC-05Keyboard-only form completionAccessibility＋

REQ-04 · Accessible workflow · DESIGN ONLY / NOT EXECUTED

StepsComplete the form using Tab, Shift+Tab, Enter and Space; trigger and resolve an error.

Expected resultFocus remains visible, order is logical, and errors are associated with their fields.

TC-06Upload size boundaryFunctional＋

REQ-05 · Document upload · DESIGN ONLY / NOT EXECUTED

StepsUse synthetic PDF files just below, exactly at, and just above the agreed size limit.

Expected resultFiles at or below the limit are accepted; oversized files receive an actionable message.
